# Incident INC-2026-0003 — Commits de gouvernance ORCHESTRATOR sous matrice v0.2

| Champ | Valeur |
|---|---|
| Version | 1.0 |
| Date | 2026-11-22T10:49:11Z |
| Statut | **QUALIFIÉ — RÉGULARISÉ PAR D-023 — vérification AUDITOR en attente (AN-08)** |
| Auteur | ORCHESTRATOR |
| Portée | Contradiction entre la matrice de permissions `AGENTS.md` v0.2 §3 et quatre commits de gouvernance réels |
| Référence | `AGENTS.md` §3 · `templates/change_request_template.md` · `state_model.md` §7 |
| Décisions | D-023 (VALIDATOR), CHG-2026-0001 |

---

## 1. Constat

`git log --oneline` sur `dev_sprint_00` montre quatre commits attribués à l'ORCHESTRATOR :

| Hash | Message |
|---|---|
| `05f52f6` | `chore(governance): reconcile S0 transition state and record incident` |
| `c80db1c` | `chore(governance): prepare S0 audit transition awaiting validator GO` |
| `2c976d6` | `chore(governance): authorize S0 audit and provide auditor prompt` |
| `507ec41` | `fix(governance): align transition status with validator GO` |

Or `AGENTS.md` v0.2 §3, validée au CP3 par D-019, portait :

- `git commit` : **interdit** pour l'ORCHESTRATOR, autorisé pour le BUILDER ;
- `git push` sur `dev_sprint_XX` : **interdit** pour l'ORCHESTRATOR, autorisé pour le BUILDER ;
- mais `state.json`, `docs/**`, `sprints/**`, `debt_report/**` : **écrits** par l'ORCHESTRATOR.

L'audit S0 (`audit_report/S0_audit.md` §10) a qualifié ces modifications de « conformes aux rôles », ce qui contredit la matrice. **L'audit n'a pas identifié cette anomalie** ; elle est enregistrée ici sous le numéro `AN-08` pour reprise dans la mission AUDITOR complémentaire.

---

## 2. Cause identifiée

La matrice v0.2 confondait deux actes distincts : **écrire** un fichier de gouvernance et **committer** ce fichier. Elle donnait à l'ORCHESTRATOR la propriété exclusive des fichiers d'état et de gouvernance, sans lui donner le moyen de les versionner.

Deuxième lacune : `reference/**` (où se trouve `decision_log.md`, modifié par l'ORCHESTRATOR) ne figurait pas dans la liste des chemins possédés.

Ce constat est compatible avec la violation de rôle signalée plus tôt par le VALIDATOR (reprise du sprint échouée par l'ORCHESTRATOR) : même cause racine, périmètre de gouvernance mal délimité.

---

## 3. Qualification

| Champ | Valeur |
|---|---|
| Identifiant violation | `PV-2026-0001` (dans `state.json` → `permission_violations`) |
| Anomalie audit | `AN-08` — à ajouter par addendum, sans réécrire `audit_report/S0_audit.md` |
| Gravité proposée | **S2 (majeure)** — limitée aux fichiers de gouvernance, aucun effet sur le code ou les tests ; à requalifier en S1 si le VALIDATOR juge l'intégrité de la chaîne de rôles critique |
| Nature | Violation d'une règle **déclarée**, non d'une interdiction technique prouvée (GC-36) |

Aucune annulation, réécriture ou réorganisation de l'historique n'a été effectuée : `git reset --hard`, le force push et le merge sont interdits, et l'historique est une preuve.

---

## 4. Traitement appliqué

- Ouverture de `CHG-2026-0001` (changement planifié, classe majeure, réversibilité R1) — voir `docs/governance/changes/CHG-2026-0001.md`.
- Décision D-023 du VALIDATOR : régularisation **rétroactive** des quatre commits listés, limitée aux fichiers de gouvernance, et approbation de l'amendement de `AGENTS.md` §3.
- `AGENTS.md` porté à la version **0.3** : séparation explicite des droits de commit et de push entre fichiers de gouvernance et fichiers de code, ajout de `reference/**`, ajout de `sprint_report/**` aux livrables BUILDER.
- `audit_report/**` reste sans droit de commit explicite : ce point n'est **pas** tranché par D-023 et demeure ouvert.

---

## 5. Limites

- La régularisation est un acte documentaire ; elle ne prouve aucune permission technique (GC-36). T1 à T5 restent `NON EXÉCUTÉS`, et les permissions restent `unknown`.
- `AN-08` doit être vérifiée par l'AUDITOR dans un addendum `audit_report/S0_audit_addendum.md`, produit via une nouvelle transition d'audit. Le rapport d'audit initial n'est pas modifié.
- La régularisation ne couvre que les quatre commits ci-dessus et les seuls fichiers de gouvernance. Elle ne couvre ni le code, ni les commits futurs hors périmètre.
- L'effectivité de la nouvelle matrice reste à éprouver.
